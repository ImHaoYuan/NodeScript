### 2026-10-08 —— 批 75：执行级能力掩码与跨脚本授权（A5 第一阶段）+ MediaProjection 高清会话（§9.2）

两条轨并行开发、各自一个工作树，由协调者会话在集成树上合流（两个 merge 提交，无 squash）。

**A5 第一阶段 —— 把「脚本能碰哪些桥面」从无判据变成 deny-by-default 的执行级掩码**

- **判据与目录**（`:domain`，零 Android / 零桥）：`CapabilityMask` 是 `@JvmInline Long` 位集，
  位序取 `BridgeCapability.ordinal`，未申报位拒绝；`BridgeCapabilityCatalog` 给「命名空间 → 所需掩码」，
  方法级**整体覆盖**命名空间级（不是并集 —— 并集会让最轻的 `poolStats` 也被要求控制权，分档就白分了）；
  **未申报命名空间 = `CapabilityMask.ALL` → 一律拒**。
  `engines.stop` / `engines.status` 的**目录级**要求降到 `NONE`：路由器只看得见调用方掩码、看不见
  `runId`（那是 payload），目录一旦写跨脚本位，窄掩码脚本连**自己**都停不掉 ——
  「是不是别的执行」这条判据下沉到 handler。
- **来源档**：`TrustTier` 四档按 §11 冻结矩阵逐字取（内置/自写/第三方/打包 = 全量，**这不是安全声明**），
  矩阵之外新增 `UNKNOWN` 档取**保守档 A**（全量减 `CROSS_SCRIPT_CONTROL`/`CROSS_SCRIPT_OBSERVE`/
  `SCHEDULER_WRITE`，用户 2026-10-08 裁定，见 `design-decisions.md` 第 43 项）。
  `PACKAGED` 档同样落保守档（无验证配置时不自动升全量）。来源**只来自宿主持有的元数据**，
  绝不从桥 payload / projectId / 项目名推断 —— 那是脚本自报，不是证据。
- **单一决策链（杀 TOCTOU）**：授权快照在 `RuntimeController.start` 的同一把锁下**算一次**，
  随后 池请求 → `EngineRunRequest` → `RunIdentityIssuer.issue` → lease →
  `AuthenticatedRunContext.capabilityMask` 搬的都是**同一份对象**，下游不重算；
  `RunIdentityRegistry` 不再自己算授权（原先「预检算一套、签发算另一套」的窗口就此关闭）。
- **桥路由先授权后路由**：未覆盖 → `ERR_PERMISSION_DENIED`，且**不进请求账、不触达 handler**
  （未知命名空间也在授权之后才判「未实现」，不留探测面）。授权字段不上 wire、不从 payload 解码 ——
  与身份三字段同一条「不可自报」纪律。
- **跨脚本目标授权**（`CrossScriptAuthorizer`，纯函数）：自我操作放行；触达他人执行要
  `CROSS_SCRIPT_OBSERVE` / `CROSS_SCRIPT_CONTROL`，**且**调用方掩码必须覆盖目标掩码
  （否则低信任调用方只要有控制位就能停掉高信任执行）；目标授权查不到 → fail closed。
  「目标在不在途」由 `RuntimeController.authorizeTarget` 在同锁下判并回 `ERR_NOT_FOUND`
  —— 纯函数不拿整张在途表，不造第二份事实。
- **派生不得提权**：`engines.exec` 要求子掩码不超出父掩码（否则 exec 就是一条提权通道）；
  宿主发起的 run 是链的根，不受此限。
- **命名通道改为按发起执行私有**（名字索引按 owner 分桶，`HOST_OWNER = -1` 给宿主直投）：
  不同执行同名通道各拿各的 id，猜别人的 id → `ERR_NOT_FOUND`。改之前通道是一条绕过掩码的跨执行数据面。
- **`workManager.create` 注入 `authorizeCreate` 接缝**：**缺注入 = 全拒**（fail closed），
  且拒的时候不落盘；接缝回 `null` = 明确放行。「接缝在、回 null（放行）」与「接缝不在（拒）」
  是两种不同的「没有授权」，实现里分开表达 —— 原先的 `?: "缺判据"` 把两者混成一种，
  是六个调度测试同时红的真因。
- **行为变化（如实记账）**：无来源元数据时，跨脚本面（`engines.exec/stop/status/poolStats`）与
  `workManager.*` 对脚本拒；a11y / 截图 / 文件 / npm / 设备面保持全量。脚本默认**不能再自建定时任务**
  —— 已知功能回退，待来源元数据接入后由分级恢复。
- **设备侧三态门禁零改动**：掩码只决定「这次执行被授权用哪些桥面」，系统层给不给仍由
  `PermissionFacade` 现问系统；两张目录（设备 `Capability` vs 桥面 `BridgeCapability`）是两个枚举，不合并。
- **边界**：这不是沙箱（§11.3 第 1 条）—— 只约束桥面命名空间，不拦 Node 内建 `fs`/`http`，
  同 UID 代码仍可绕开桥直连进程与文件。本批掩码只驻内存，不落盘。

**MediaProjection 高清会话（§9.2 的另一条腿）**

- **会话生命周期**：进程级单会话账（`opening` / `openingOwner` / `current`）；API 34+ 顺序按官方要求走
  —— mediaProjection 型 FGS 起并确认 → `getMediaProjection` → 注册 `MediaProjection.Callback`
  → `createVirtualDisplay`；四个检查点各带 `releasePartial`，失败不留半开会话。
- **同意是一次性的**：API 34+ 每会话重新征询，**不做自动续期** —— 旧的「306s 超时前自动续期」口径
  在 34+ 上做不到（没有可续的持久授权），`docs/design/13-roadmap-budget.md` 的风险表与兼容矩阵
  两处措辞据此订正（`design-decisions.md` 第 44 项）。正路是 `foregroundServiceType="mediaProjection"`
  的前台服务，它本身就免除旧上限；到点（用户撤销 / 系统停止）如实报错并引导重新授权，不假装续上了。
- **幂等与迟到回调**：释放幂等（VirtualDisplay / ImageReader / MediaProjection / FGS）；
  `onProjectionStopped` 按投影身份认领，**先清 `current` 再释放**；迟到的旧回调影响不到新会话。
- **帧**：遵守 `rowStride` / `pixelStride` 拷贝像素、及时 `close` `Image`，经**共享的**
  `ImageAnalyzer.ingest` 入表 —— 与 a11y 截图帧同表同号段，跨帧源匹配（`images.findImage`）才成立。
- **同意征询**：`ScreenConsentRequests` 单请求状态机，`outstanding`（已交给系统）与 `waiter` 分开；
  `revoke` 只撤 waiter、`deliver` 只投当前轮；inbox 忽略非 granted、`claim()` 恰好一次。
  `MainActivity` 用 `registerForActivityResult` 收结果，`requestScreenConsentDetached` 带主线程快路径
  （避免"等自己"），`awaitConsent` 在调用方协程里登记 waiter 并在取消时 `revoke(ticket)`。
- **资源收口**（结构性，不靠记性）：`ConnectionResourceRegistry` 提供 `register(close)` / `revokeAll()` /
  `release()`，恰好一次；撤销后再登记立即触发；teardown 路径上的异常吞进 `onError` 绝不外抛。
  `NewlineFrameServer` 把注册表挂在连接对象上，abort / dispose / EOF 三条路都 `revokeAll()`；
  `AuthenticatedRunContext.resources` 由**接入端**在认证成功后装填（可变字段而非构造参数 ——
  构造点不该认识桥的资源形状）。于是「脚本崩了但投屏还挂着」这条漏在结构上不成立。
- **前台服务与熄屏裁剪**：`ProjectionForegroundService`（`foregroundServiceType="mediaProjection"`、
  `exported=false`）；`ProjectionForeground` **先登记 waiter 再** `startForegroundService`，
  超时 `abandon(generation)`，有界废弃世代集，无 `CountDownLatch`。熄屏收会话（§8.8）：
  keyguard 下投屏给的是**黑帧**，留着只会让脚本拿到黑图还以为成功 —— `ScreenOffGuard` 同步、幂等、不抛。
- **诚实边界**：真机行为未在本机验证（无设备）；`abortConnection` 对「子进程继承了桥 socket fd」
  这一形态**没有覆盖**（那种情况下脚本死了也不产生 EOF），需要 `runId → connectionId` 映射，
  属新范围，未在本批夹带半成品。
