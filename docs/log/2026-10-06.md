### 2026-10-06 —— 批 62：文件日期改 yy-MM-dd HH:mm + 夜间顶栏/菜单/底栏统一 #161E27 + 编辑器不折行（横向滚动）与双指缩放

- **来源**：用户四条 —— ① 文件列表的日期显示改成 `26-06-24 22:32` 这种；② 夜间模式下**顶栏、菜单栏、

  **关闭自动换行**（不折行 + 左右滚）。
- **① 日期：三档 → 一个格式**。原口径是 TG 会话列表 `formatDate` 的移植（今天 `HH:mm` / 今年 `MM-dd` /
  跨年 `yyyy-MM-dd`）—— 同一列里三种粒度，扫一眼分不清"这个文件是哪天的"。改成固定 `yy-MM-dd HH:mm`
  （年月日两位、行宽稳定）。连带把 **`nowMillis` 参数整条链拆掉**（`ScriptFileRowUi.formatTime` /
  `.of` / `ProjectState.of` / `MainActivity` 调用点）：文案不再依赖"现在几点"，留着就是个没人读的参数；
  `DateTimeFormatter` 提到文件级 `FILE_TIME`（原先每次格式化现建 3 个，一屏几十行就是几十次 pattern 解析）。
  测试同步：`ProjectStateTest` 的 `nowMillis` 实参全删，三档断言换成一条"一个格式走到底"（含用户给的
  那个例子 `26-06-24 22:32` 与跨年 `25-03-02 08:00`）。
- **② 夜间三处旧灰**：`ActionBar` 缺省底色从 `surface`（0xFF232326）换成 `background`（#161E27）、
  `TabBar` 胶囊底同样换 —— 浅色档 `background` 与 `surface` **同为白**，所以这两处在日间零观感变化；
  底栏胶囊的分层靠 shadow(10dp) + 圆角（浅色档本来就是"白胶囊贴白屏底"）。`menuBackground`
  0xFF282829 → #161E27，`menuSeparator` 0xFF1E1E1F → **0xFF0C141D**：组间那道"槽"原先 = 菜单底每通道
  −10，菜单底平移之后槽也得平移同样的量，否则槽比菜单底更亮、读成一条接缝。**故意没动**的：
  `surface`（卡片色，设置页卡片仍用它）、`sheetBackground`（长按"更多"面板）、`roundButtonBackground`
  （回到顶部那颗）。
- **③ Telegram 那颗钮：这份 clone 里没有**（按用户口径"找不到就算了"，钮保持批 61 的形态）。证据留档，
  下次不必重搜：`ChatActivity.java`（47,272 行）里 `scrollToBottomButton` / `toBottomButton` / 大小写
  不敏感的 `scrolltobottom` **全 0 命中**；该文件 20 处 `setImageResource` 里没有任何下箭头；
  `res/` 下 `**/*[Bb]ottom*` 只有 `*_bottom.9.png` 与 BottomSheet 系列，没有 `ic_bottom` 这类下箭头

  - **不折行靠约束，不是参数**：`BasicTextField` **没有 `softWrap`**（先按"加个 `softWrap = false`"写，
    编译器直接 `No parameter with name 'softWrap' found`）。做法是外层 `Modifier.horizontalScroll` 给
    内容**无限宽** —— 排版拿不到宽度上限就不会折行，字段宽度跟着最长的行走；`widthIn(min = 视口宽)`
    补另一头（正文比一屏窄时也占满可视宽度，右边那片空白才点得到、落得了光标）。
  - **行号槽因此整块简化**：逻辑行 = 视觉行，行号列就是 `1..lineCount(text)`；批 61 为折行写的
    `logicalLineRows` + `EditorScroll.gutterLabels` + 3 条测试**整块删掉**（口径被本批推翻，原地记这一笔）。
  - **缩放改的是字号/行高/字距**（`TextUnit * zoom`），不是 `graphicsLayer` 拉伸画面 —— 拉伸只改画面
    不改排版，滚动范围、行号位置、"屏幕外还有几行"会全部对不上。倍率夹在 0.6–3 倍（≈8.4sp–42sp），
    行号槽宽度跟着缩放，行号与正文的对齐关系不变。

    "横向拖动"，不在这趟里拦下来缩放会跟横向滚动打架。
  - `EditorBody` 新增两段逻辑后撞 `LongMethod`（122 > 120）→ 把"正文与行号槽**共用**的那套字体度量"
    提成两个纯函数（`editorCodeStyle` / `editorGutterStyle`），回到线内。**没有**动阈值、也没有拆一个
    只为过门的空壳组件。

### 2026-10-06 —— 批 61：编辑器行号槽 + 点空白落文末 + 右下跳转钮（气泡数屏幕外行数）+ 夜间屏底改 #161E27 + 项目页行间分割线

- **来源**：用户一整轮编辑器要求 —— ① 正文左边加**行号**、用一条淡灰竖线分割（VSCode/IntelliJ 那种）；
  ② 文件下方是空白时，点空白把光标落到**文末**开始编辑；③ 优化**字间距**，别让字连在一起；
  ④ 编辑器内部**右下角**加一颗**圆形、白底、淡灰边**的按钮：默认"去最底部"，手指往下滑变"去最顶部"、
  往上滑变"去最底部"，按钮上方一个小气泡显示屏幕外还有多少行；⑤ 日夜两套配色都要适配，
  **夜间模式的黑色改成 `#161E27`**；⑥ 主页"项目"里每两行之间加一条淡灰分割线。
- **① 行号槽（`EditorBody` + `EditorScroll.gutterLabels`）**：行号那一列由**排版结果**算出来，不是文本
  自己数出来的 —— 正文**保持折行**（没有改成横向滚动：手机屏宽下十几二十个字就折了，为每个长行左右拉
  一次是拿"能读"换"行号好对齐"），所以一个**逻辑行**会占好几个**视觉行**；行号只写在**第一个**视觉行上、
  续行留空（与 Acode 一致）。这个映射只有 `TextLayoutResult.getLineForOffset` 知道（`logicalLineRows`），
  拼那一列是纯函数（`gutterLabels`，测试钉住"续行留空"与"行数不能少"）。槽宽按**最大行号**的位数留
  （三位数不该按一位数留宽），竖线画在槽的**右缘**（`drawBehind`，贴着正文一侧、不占正文宽度）；
  行号与正文**同一个 `TextStyle` 派生**（只换对齐与颜色）—— 字号/行高/字距只在一处定义，否则第 n 个
  数字会逐行偏离第 n 行。
- **② 点空白落文末**：正文那一层的最小高度 = **一屏**（`heightIn(min = maxHeight)`），手势挂在整行上
  （在内边距之外，坐标就是整行的坐标），只认**正文下方、且不在行号槽里**的那块空白：
  `contentHeightPx`（`onTextLayout` 报回来的正文高度）以下才动手 → 选区设到文末 + 请求焦点。
  编辑器状态从 `String` 换成 **`TextFieldValue`**（光标位置也是编辑器状态，"主动设选区"要求选区可控；
  `composition = null` 是收掉输入法正在组的那一段词）。**只有正文真的变了才标脏**：点空白只是挪光标，
  那时亮起"保存"、退出还问"有未保存的修改"就是在骗人。
- **③ 字距**：`letterSpacing = 0.5sp`（等宽字体下 CJK 与数字挤在一起最难认）。
- **④ 右下那颗钮**（`EditorJumpChip`）：正圆 44dp、**白底 + 1dp 淡灰描边**（用户口径"白色"，深色也
  不翻；描边跟着主题走：浅 `0xFFDCDCDC` / 深 `0xFF4A5563`），图标是 `↑`/`↓`。方向**由手指定**（用户口径）：
  往下拖 = 内容往回走 = 你在往上看 → 钮变"去最顶"、气泡数**上方**还有几行；往上拖反之；默认（还没拖过）
  是"去最底"。判读走 `snapshotFlow`，气泡那个数走 `derivedStateOf` —— 直接读 `vScroll.value` 会让整块
  编辑面**每滚一帧重组一次**。气泡只在正文**超出一屏**时出现（`overflows`，上下留白要从视口里扣掉）。
  **跳完把方向翻过来**：刚去了顶部，下一次有用的是"去底部"—— 不翻的话钮会停在"去顶部"上、再点一次
  什么都不发生（用户口径只规定了"手指方向 → 钮的方向"，跳转后的方向是这里补齐的）。正文下方留 60dp
  让位（钮是浮层、不参与布局），滚到最底时最后一行正好停在钮上方。
- **⑤ 夜间屏底 `#161E27`**：`background`（屏底）与 `surfaceMuted`（设置/管理/任务中心三屏的屏底，
  night 里本来是**纯黑**）一起改 —— 只改前者会出现"设置页比首页更黑"的断层；`fieldBackground` 是
  "白 7% 叠屏底"的**配方值**，底换了而配方不换那个结论就不成立，跟着重算 `0xFF282829 → 0xFF262E36`。
  **这是本仓故意偏离 TG night `windowBackground`（`0xFF181819`）的一处**，KDoc 里写清了。纯黑的
  `divider` 与 `0xFF0B0B0C` 的 `graySection` **没动**（TG 的深色语义是"比卡片更暗的一道槽"，不是
  "比底更亮的一条线"）；本批新加的两条线也用 `divider`：浅色 `#E6E6E6` 正是用户要的淡灰，深色下则是
  一道暗槽（与浅色那档的对比度相当）。
- **⑥ 项目页行间分割线**：`items` → `itemsIndexed`，每行之后画一条 1dp `divider`，**最后一行不画**
  （末尾挂一条悬空的线读起来像"下面还有内容"）；左内缩 = 12 + 52 + 12 = 76dp，与**文字左缘**对齐
  （线从头像底下穿过去，"头像属于哪一行"就糊了）。

  `:app:assembleDebug` 绿；`ui/detekt-baseline.xml` **只新增 2 条**（`EditorBody` / `EditorJumpChip`
  两个 Compose 组件撞 `FunctionNaming` 的默认规则 —— 本仓同类存量 72 条，惯例是进基线；新常量走
  `EDITOR_CHIP_FADE_MILLIS`，没有为了绕规则把组件名写成小写）。

- **① Telegram 源码**：`git clone --depth 1 --single-branch` 到仓库根 `Telegram/`（14,068 文件 /
  384.2 MB，自带 `.git`）。`.gitignore` 追加 `/Telegram/`（`git check-ignore -v` 实测命中），
  不入库的理由写在那一行上面：体积 + 别人的仓库自带 `.git`。**克隆成功，没有向用户要颜色**。
- **② 夜间模式颜色（TG 有，而且是三份来源叠出来的）**：`TMessagesProj/src/main/assets/{day,night}.attheme`（裸键 +
  有符号 32 位 ARGB）、`ActionBar/ThemeColors.java`（缺省值）、`Theme.java`（取值顺序 = attheme 覆盖
  ThemeColors）。本仓调色板本来就按这个口径逐键取，本批**对出并修掉 4 处漂移**：深色 `divider`
  （`night.attheme` = `0xFF000000` 纯黑 —— 深色下分隔线是"更深的槽"而不是更亮的线）、深色 `barSubtitle`
  （`0x73F2F2F2` = 45% 白）、深色 `pressedOverlay`（`0x16FFFFFF`）、浅色 `pressedOverlay`（`0x121A1D21`）。
  **故意不动**的三处（KDoc 里写清为什么）：`accent`（night 里两个键给出两个蓝，本仓取
  `actionBarTabActiveText` 那个）、`success`（attheme 把 `chats_onlineCircle` 覆盖成蓝，本仓保留
  ThemeColors 的绿）、`error`（night 未设 `chats_sentError`，本仓取自己那档）。顺带订正 `Theme.kt` 里一处
  假声明（`text_RedRegular` 在 `day.attheme` 里根本没被设过，`0xFFCC2929` 是 ThemeColors 缺省）。
- **③ 切换动画：卡顿的根因是"同步软件重画"，不是动画本身**。TG 的做法在 `LaunchActivity` 的
  `needSetDayNightTheme`：`ViewAnimationUtils.createCircularReveal(toDark ? 容器 : 那张底片, x, y, toDark ? 0 : R, toDark ? R : 0)`，
  半径 = 圆心到**最远那个角**的距离，时长 **400ms**，缓动 `Easings.easeInOutQuad` =
  `CubicBezierInterpolator(0.455, 0.03, 0.515, 0.955)`，配 `DialogsActivity.switchingTheme` 的重入守卫。照它改了四处：
  1. **抓帧从"同步软件重画"换成 `PixelCopy`**（TG 走 `AndroidUtilities.getBitmapFromWindow`）：原先是
     `view.draw(Canvas(bitmap))`，即**在点击那一刻让整棵视图树在 CPU 上重画一遍**（满屏软件光栅化，
     几十毫秒全落在主线程上）—— 这才是"卡"的主因。现在只是把 GPU 已经画好的这一帧回读出来，挂在协程
     上等回调；拿不到 Window / PixelCopy 报错时仍退回软件重画，再不行退化成纯色底（三级降级，永不把
     换主题升级成崩溃）。加 250ms 超时兜底：`PixelCopy.request` 在窗口正被销毁时可能一次回调都不来。
  2. **缓动换成 TG 的 `EaseInOutQuad`**（`Motion.kt` 新增；KDoc 写明**别拿它当通用缓动** —— 本仓其余
     过渡仍是 `EaseOutQuint`）。
  3. **方向**：TG 两个方向裁的是**不同的视图**（转深色裁新内容、转浅色裁那张旧底片），所以不是同一张
     画的镜像。收成两个纯函数（`ThemeReveal.circleFraction` + 新增 `ThemeReveal.oldFrameInside`），并加测试钉
     **端点**：两个方向的起点都必须是整屏旧主题、终点都是整屏新主题 —— 写反了动画会从"新主题那一屏"
     往回长，而中段看过去一样是个圆，只有头一帧看得出闪。
  4. **揭示期间不再重组**：揭示状态只被协程与绘制闭包读（不进组合）—— `MaterialTheme` 的 colorScheme 是
     **static** CompositionLocal，置位/清位原本会各放大成一趟整棵界面重组；每帧的 `Path` 改成复用同一个
     对象（400ms × 60~120 帧，每帧一次分配正是"卡一下"的来源）；底片只画它该在的那一侧
     （`ClipOp.Difference`/`Intersect`），省掉一层满屏填充。
- **④ 三处 ⋮**：顶栏（项目页 + 设置页）与文件行尾**都不再用 `Text("⋮")`**（那个字符的粗细由系统字体决定、
  没法比大小），改成同一个画出来的 `Glyph(GlyphKind.MORE_VERT, …)`，只差一组参数：顶栏 24dp × 1.3
