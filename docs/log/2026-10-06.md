### 2026-10-06 —— 批 53：B11 引擎 stderr 捕获 + 崩溃摘要归档

- **驱动**：backlog **B11**（P1）—— 引擎排水线程对子进程 stdout/stderr「读即弃」，脚本崩溃说不清理由（`RunRecord` 只有 `state`），原生层（`libnode.so` 装载失败、addon `fprintf`）同样只有丢掉这一条路。与 A7「吞异常」同类，但这条是**进程边界上的吞**。
- **捕获（`:engine:node-process`）**：`ProcessBuilderLauncher` **去掉** `redirectErrorStream(true)` —— 合流会丢掉「这是 stderr 写的」的分辨，而病因几乎全在 stderr。stdout 那条通道**仍然只排空不存内容**（它存在的唯一目的是防管道写满反压），另起一条 stderr 排水线程把字节喂给**有界环形尾 buffer**（`StderrTail`：字节级、上限 `RunSummary.MAX_DETAIL` = 4096、满了丢最老）。**取快照时才整体 UTF-8 解码**，故跨 `read` 切分的多字节字符不会被撕裂（头部截断处退化成 U+FFFD，尾端永远干净）。`SpawnedProcess` 新增 `stderrTail: String`。
- **契约（`:domain`）**：`ScriptEngine.lastRunSummary(): RunSummary?` **带缺省实现回 null** —— 老替身（`UnavailableEngine` 等）零改动；`RunSummary(exitCode, stderrTail)` + `MAX_DETAIL`。填充时机钉在 `status()` 的**自然退出**分支（`exitValue != 0` → CRASHED；`== 0` 也快照，诊断读口无害）；**请求停止（143）与强杀（137）不填** —— 那两个退出码是终止手段的产物，不是病因。`execute` 开头清空上次摘要。
- **传递链**：`RuntimeController.Completed` 的失败类 `StopTimeout`/`Killed`/`UnknownRun` 从 `data object` 改 **data class**（带 `summary`），摘要取在 **`pool.release` 之前**（槽位还在本 run 手里时才能问引擎；收走后同槽可能已被下一次 execute 复用，那时问到的就是别的 run 的摘要）。`:app` 的 `ControllerRunDispatcher` 把摘要**摊平**成 `RunOutcome.Failed/Crashed` 的 `exitCode`/`crashSummary` **两个裸字段**。
- **架构门逼出来的口径（本批最值得记的一条）**：`RunOutcome` 原本想直接折 `domain.engine.RunSummary`，`:app-service:scheduler` 的 `ArchitectureTest`（禁 `com.autoscript.domain.engine..`）**当场红**。裁定：scheduler 只碰 `domain.scripts` 脚本模型，`RunSummary` → 两裸字段的摊平放在**同时看得见两侧类型**的 `:app` dispatcher；消费端 `RunRecord` 要的恰好就是这两个字段，折一次是纯转手、零信息增益。理由写在 `RunOutcome` KDoc 里（下次有人想折整个摘要会先读到这段）。
- **归档**：`RunRecord` + `exitCode`/`crashSummary`（全默认 null），`FileRunArchive.ArchiveCodec` **append 式**加两字段、parse 走 `optLong`/`optStr` → **旧 journal 行无需迁移即可 replay**（缺字段如实 null）。`IntentStore` 的 `toStored`/`fromStored` **不动**（`message` 已折进 `detail`；摘要的权威落点是 `RunRecord`，不重复持久化两处）。
- **呈现面（只到数据层）**：`RunRow` +2 字段、`TaskCenterRead` 映射、`RunRowState.crashSummary`、新 `RunStateText.describe(state, crashSummary)`（有摘要拼「崩溃：<病因>」，无则退回原句；非 CRASHED 不拼）。**`RunRowState.of` 已改走带摘要那一支** —— 崩溃行的念法不再是「被杀/OOM/看门狗」的套话。**但任务中心卡不新增渲染**：批 41 用户拍板摘掉未结算块，这一栏当前没有渲染点，本批只把**数据面 + 念法**备好，摘要是将来项目历史列表的消费者。
- **测试**（假缝 + 真进程两侧）：`NodeProcessEngineTest` 断言 CRASHED 时摘要带退出码 + 尾部、exit 0 也快照、下次 `execute` 清空；**`NodeProcessEngineRealSpawnTest` 真起 node**：写 stderr 后 `exit 3` → `lastRunSummary` 带 `exitCode=3` 与病因原文（真管道真排水真环形缓冲，假缝钉不了）；只往 stdout 写噪声的崩溃**摘要里不得出现** stdout 内容（证 `redirectErrorStream(false)` 真分了两条通道）。`RuntimeControllerTest` 三条 Completed 断言改带摘要；`ControllerRunDispatcherTest` 软停 → `Failed(exitCode, crashSummary)`、崩溃结算 → `Crashed` 带两字段（新增 `FakeEngineForDispatcher.statusAfterAutoExit` 让替身能自报 CRASHED）；`FileRunArchiveTest` 加**往返**与**旧行向后兼容**两例；`SchedulerArchiveTest` 加 outcome → `RunRecord` 两字段折档 + 成功路径如实 null；`TaskCenterReadTest` / `TaskCenterStateTest` 补投影与文案。
- **门**：十三模块同源 Gradle 测试（`./gradlew :domain:test … :app:testDebugUnitTest -PskipNpmE2E`）全绿零跳过；全模块 `lintDebug`、`:app:assembleDebug`、`./gradlew jacocoTestReport detekt` 全过；文档链接门 **407 条**全存在。
- **未做（如实登记）**：① **真机冒烟仍缺** —— 引擎二进制还没进 APK（**B5** 另案），本批的真进程验证止于桌面 `node`；② 全量 stdout/stderr 流式通道（桥 `console` namespace）是另一条面，本批只做尾部摘要；③ **不做去抖/首行忽略**（Node 启动噪声治理）—— 只做确定性截断，见了真数据再调。
